`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーからフィルタリングの動作を確認しました。次は、明確に定義した品質保証 (QA) プロセスを持つカスタムエージェントに、これらの機能をまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリングの issue に照らしてその指摘をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を開く前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタムエージェントを使うと、この QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的なバージョンです。プロファイルでは、エージェントの目的、指示、利用できるツールを説明します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

ここまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件の確認と結果の報告に、これらの機能をどう使うかを Copilot に伝えます。QA プロファイルがこれらを置き換えるわけではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、Copilot に再利用可能な QA プロファイルを作成してもらいます。プロファイルには、QA で実行するチェックと、守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、カバレッジが不足している場合はテストを追加してください。

   各要件について、裏付けとなる証拠とともに pass、fail、blocked のいずれかで報告してください。実装コードを変更する前には確認を求め、変更をコミットしたりプルリクエストを開いたりしてはいけません。

   まずはレビューできるよう、プロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA ワークフローと制約をプロファイルに反映したことを確認します。これにより、検証だけを求めているときに、エージェントが不完全な指示で機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は省略できますが、含めるとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を確認し、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を示して報告し、実装コードの変更前に確認を求め、変更のコミットやプルリクエストの作成を行わないことを確認します。
5. これらの責任や制約が抜けている場合は、続行する前に既定のエージェントへプロファイルの修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトエージェントを読み込みます。プロファイルを作成したら、同じフィルタリングの会話を再開し、QA を選択して、すでにコンテキストに含まれている issue と計画の決定を利用できるようにします。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェント一覧に表示されない場合があります。コマンドを実行すると有効になります。

2. 次のプロンプトを使い、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   フィルタリング機能を issue と計画で決めた内容に照らしてレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントの作業が始まります。
4. 作業が完了したら、レポートを読みます。
