GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行するなど、自律的に作業します。作業は開発者のマシン上でリアルタイムに進むため、VS Code の Copilot Chat では各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れたり取り消したりできます。また、エディターを離れずに追加のプロンプトを送って会話を導き、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始める代わりに、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが実行する各ステップ、調査するファイル、実行するコマンド、提案する編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットにインライン表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中は、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインライン表示されます。
   - 変更を受け入れるには **Keep** を選択します。
   - 変更を元に戻し、エージェントにもう一度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツール呼び出しの許可を求められると、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも依頼します。同じチャットセッションを続けることで、エージェントは前の作業のコンテキスト、変更したコンポーネント、スタイルの方法、設定の保存に使ったパターンを保持できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   よくできました。ハイコントラストの切り替え機能に加えて、ライトモードの切り替え機能を追加してください。ライトモードにも同じ方法を使い、ローカルストレージに設定を保存して、同じ UI 領域から操作できるようにしてください。ハイコントラストモードとライトモードは、利用者が独立して有効にできるようにしてください。
   ```

2. エージェントは既存の変更を調べ、そこから続けてライトモードを追加します。
3. ハイコントラストの場合と同様に、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合は (たとえば、好みでない方法で切り替えユーザーインターフェイス (UI) をリファクタリングしようとする場合)、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示すると、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、方向を修正する場合は「3 つ目の切り替え機能を追加せず、既存の設定パネルにライトモードを統合する」、範囲を広げる場合は「両方の切り替え機能にキーボードショートカットも追加する」といった例があります。

## 作業ファイルをレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンとして、Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、セッション中の作業を監視して導きました。ファイル編集をその都度レビューし、変更を受け入れるか拒否し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり拒否したりしました。
- 追加プロンプトで進行中のセッションを導きました。
