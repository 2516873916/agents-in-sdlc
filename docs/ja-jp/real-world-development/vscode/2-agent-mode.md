アプリケーションの単純な更新でも、通常は複数のファイルを変更し、テストを実行するなどの作業が必要です。開発者は、必要なファイルを探し、変更を行い、テストを実行して、デバッグし、更新し忘れたファイルに気付いて再度変更する、といった作業を繰り返します。

このような場面で Copilot Agent Mode が役立ちます。

Copilot Agent Mode は、IDE 内でより自律的に作業するように設計されています。開発者と同様に、プロジェクト構成を調査して関連ファイルを特定し、必要な更新を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。Agent Mode を使って、サイトに新しい機能を導入する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、agent mode と cloud agent は異なる利用体験を提供します。agent mode は IDE 内で作業し、短いフィードバックサイクルでやり取りできます。cloud agent はチームメンバーのように非同期で作業し、issue とプルリクエストを介して開発者とやり取りします。

この演習では、次のことを学びます。

- Copilot Agent Mode がプロジェクトを調査し、関連ファイルを特定して、複数ファイルにわたる変更を行う方法。
- GitHub Copilot Agent Mode が UI とデータレイヤーにわたって新機能を実装する方法。
- コードベースにマージする前に、Copilot Agent Mode が生成した変更とテストをレビューする方法。

## シナリオ

ゲーム一覧が増えているため、利用者がカテゴリとパブリッシャーで絞り込めるようにします。前の演習でパブリッシャーヘルパーを追加しました。次は Copilot Agent Mode を使って、残りのデータレイヤー、UI、テストを完成させます。

## Tailspin Toys ウェブサイトを実行する

変更を加える前に、Tailspin Toys ウェブサイトの現在の機能を確認します。

ウェブサイトは、開発者をテーマにしたボードゲームのクラウドファンディングプラットフォームです。ゲーム一覧を表示し、ゲームの詳細を確認できます。単一の Astro アプリで、ビルド時にページを静的 HTML としてレンダリングします。ページはフロントマターから Drizzle のオブジェクト関係マッピング (ORM) を介してローカルの SQLite データベースを直接クエリします。独立したバックエンドのアプリケーション プログラミング インターフェイス (API) やクライアント側のユーザーインターフェイス (UI) フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、インタラクティブな動作は標準のドキュメント オブジェクト モデル (DOM) API を使う小規模で範囲を限定した Astro `<script>` で追加します。

### ウェブサイトを起動する

ウェブサイトを簡単に実行するため、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. Codespace に戻ります。前の演習を終えて `main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、Codespace で新しいターミナルを開きます。
3. フィルタリング作業用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行してウェブサイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を含むバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を、<kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら選択して、ウェブサイトを開きます。

> [!NOTE]
> codespace でターミナルに表示された localhost URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは、ウェブサーバーをホストする codespace へのプライベートトンネルです。

### ウェブサイトを確認する

ウェブサイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: タイトル、画像、説明とともにボードゲームの一覧を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、そのタイトル、説明、パブリッシャー、カテゴリなどの情報を表示する詳細ページが開きます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 1. 以下の演習を始める前に、codespace に戻って Copilot Chat パネルを開きます。
> 2. **New Chat** を選択して新しい会話を始めます。
> 3. モードとモデルの選択は演習によって異なります。必要な場合は各手順で説明します。

ウェブサイトの初期実装は動作しますが、新しい機能を追加したいと考えています。まずバックログを確認します。テンプレートからプロジェクトを作成すると、issue のバックログも自動的に作成されています。GitHub Copilot に項目を表示してもらいましょう。

1. Chat ビューのエージェントドロップダウンから **Agent** を選択します。**Agent** エージェントは、自律的に計画を立て、複数ファイルにわたる変更を実装し、ターミナルコマンドを実行して、ツールを呼び出します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデル一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が特定のモデルを推奨するものではありません。ワークショップの作成時に Claude Sonnet 4.5 を使用したため、手順に含めています。コードの提案を比較的揃え、作業を進めやすくするためです。ただし、大規模言語モデル (LLM) は確率的に動作するため、ワークショップに示した内容と異なる提案が表示されることがあります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使う場合がありますが、タスクは同様に完了できるはずです。

3. 次のプロンプトを Copilot に送信して、バックログの issue を確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。利用者にとって有用なものを基準に優先順位を付けるのを手伝ってください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot は、利用者にとって最も有用だと考える項目を基準に優先順位も付けています。

## 指示ファイルを確認する

エージェントにコードを生成させる前に、Copilot に作業のコンテキストを提供する指示ファイルを確認しましょう。ウェブサイトへの機能追加方法に関するコンテキストが記載された [user interface (UI)](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md) ファイルを使います。

1. codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加に関する全般的なガイダンスを確認します。内容には次のものがあります。
   - アーキテクチャの概要。
   - コンポーネントの設計、テスト可能性、アクセシビリティに関する原則。
   - Astro、Tailwind CSS、Drizzle などのファイル種類ごとの指示へのリンク。

> [!TIP]
> 指示ファイルから、他の指示ファイルとプロジェクト内のファイルを参照できます。パスは指示ファイルからの相対パスです。これにより、再利用や複雑な内容の分割が容易になり、Copilot に従ってほしい例やテンプレートを示せます。

## フィルタリング機能を実装する

フィルタリングを完成させるには、少なくとも 3 つの異なる更新が必要です。

- データレイヤー (`src/lib/`) に残りのフィルタリングロジックを追加または調整する。
- フィルタリング動作のテストを追加または更新する。
- ゲーム一覧ページにフィルタリング UI を追加する。

さらに、コードベースにマージする前にテストを実行し、合格させる必要があります。Copilot Agent Mode にこれらの作業を依頼しましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択して、指示ファイルを追加します。

   ![UI 指示ファイルの選択例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェントドロップダウンで、引き続き **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

4. モデルが引き続き **Claude Sonnet 4.5** であることを確認します。
5. バックログの関連 issue に基づいて機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   関連する GitHub issue の要件に基づいて、サイトにパブリッシャーとカテゴリによるフィルタリングを追加してください。前の演習で追加したパブリッシャーヘルパーは維持し、必要に応じて調整しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが合格することを確認してください。サーバーはすでに起動しているため、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調査し、機能に関連するファイルを探します。データレイヤーのヘルパーと UI、テストを見つけてファイルを変更し、テストを実行します。

   ![Copilot がプロジェクトのファイルを調査している](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行など、複数の作業を行います。タスクやコードベースの複雑さによっては数分かかることがあります。作業中、コードエディターに **Keep** と **Undo** が表示される場合があります。Copilot の作業が完了するとすべての変更に **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot に求められたら、**Continue** を選択してテストを実行します。

   ![Copilot Chat ペインに表示された、テスト実行の確認ダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot はタスクを完了してエラーを検出しなくなるまで、コード生成とテストを繰り返します。

   ![Copilot Agent Mode のセッション完了画面](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードを確認し、問題がないか調べます。

> [!CAUTION]
> Copilot や他の AI ツールが生成したコードは、必ずレビューしてください。

10. ウェブサイトを起動したブラウザーに戻り、新機能を確認します。
11. 動作を確認してコードのレビューを終えたら、Copilot Chat ウィンドウで **Keep** を選択します。

おめでとうございます。この演習では、GitHub Copilot Agent Mode を使って Tailspin Toys のウェブサイトに機能を追加しました。次の方法を学びました。

- Copilot Agent Mode がプロジェクトを調査し、関連ファイルを特定して、複数ファイルにわたる変更を行う方法を確認しました。
- GitHub Copilot Agent Mode が UI とデータレイヤーにわたって新機能を実装する方法を確認しました。
- コードベースにマージする前に、Copilot Agent Mode が生成した変更とテストをレビューしました。

### ボーナス演習 — ページネーションを実装する

ゲーム一覧が増えるにつれ、ページネーションが必要になります。この演習で学んだことを使って、Copilot にサイトのページネーションを実装するよう依頼します。次の手順で作業してください。

1. 既存の指示ファイルを使うなど、既存のベストプラクティスに従います。
2. ページサイズを利用者が選択できるようにするか、値を固定するかなど、ページネーションの方法を検討します。
3. 希望する実装に必要なガイダンスを Copilot に提供するプロンプトを作成します。
4. Copilot に変更やコンテキストを追加で依頼し、反復します。これは Copilot を使う通常のワークフローです。
