Space Quiz を GitHub Pages にデプロイして、誰でもアクセスできる場所に公開しましょう。Copilot はワークフローの準備とデプロイの案内を行いますが、変更をレビューし、サイトが公開されたことを確認するのは開発者です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages の構成を依頼します。
- マージ前にワークフローとプルリクエストをレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、利用者が簡単に試せる方法が必要です。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに公開 URL から利用できるようになります。

## Copilot にサイトのデプロイを依頼する

公開設定とデプロイを Copilot に依頼するため、`space-quiz` のセッションからプロンプトを送信します。

1. 次のプロンプトを送信します。

   ```plaintext
   このリポジトリで GitHub Pages を有効にしてください。必要に応じてウェブサイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更でプルリクエストを作成し、必須チェックに合格したらマージしてください。デプロイを監視して成功するまで確認し、公開サイトの最終 URL を報告してください。Pages の有効化またはマージの権限がない場合は、承認または実行が必要な操作を正確に伝えてください。サイトが公開されるまでは成功と報告しないでください。
   ```

> [!WARNING]
> このプロンプトでは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、差分、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローをレビューしてデプロイを確認する

ワークフローと公開状態を検証して、エージェントの報告だけに頼らず、サイトが利用可能であることを確認します。

1. README が、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ビルドとデプロイの各ステップを含め、プルリクエストの変更をレビューします。
3. 必須のプルリクエストチェックに合格した後にのみマージします。
4. GitHub Actions のデプロイ実行を追跡し、成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages を有効にできない場合やプルリクエストをマージできない場合は、提示された手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは、作業を完了とみなさないでください。

## まとめと次のステップ

Space Quiz をライブサイトとして公開し、エージェントの報告に頼らずデプロイを確認しました。具体的には、次のことを行いました。

- Copilot に GitHub Pages のデプロイ構成を依頼しました。
- マージ前にワークフローとプルリクエストをレビューしました。
- デプロイの進行を確認し、公開されたサイトを検証しました。
